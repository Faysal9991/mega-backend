# ADR 0014: durable gifting, validated assets and session-bound push

Status: owner-authorized implementation, independent review pending. Baseline c749cec.

The delivery module owns catalog presentation/version snapshots, validated media assets, push bindings/preferences/history and recoverable delivery intents. Wallet owns all financial posting; Live owns room/publishing eligibility; Profiles owns avatar writes. SDK and SQL stay in infrastructure adapters. The narrowly scoped outbox is a transactional delivery mechanism, not a general job framework; River remains the chosen future durable application-job framework. This batch needs bounded, fenced claim/ack/retry of three concrete intent types rather than an additional scheduler/migration owner.

A live-gift request binds room/session, recipient, gift and quantity to actor-scoped idempotency. Before posting, resolve the immutable database catalog version and explicit active_publishers recipient mode under the existing security/financial lock. Both parties need current verified provider presence and active room membership; the recipient additionally needs current publishing and agency compatibility. Existing configurable agency/non-agency distribution, inclusive-diamond VAT, largest-remainder rounding and balanced ledger remain authoritative. The database catalog is the authoritative live-gift price; old Wallet non-room gifting keeps its existing policy catalog and produces no room event. Existing financial policy snapshots remain byte/JSON-equivalent to their immutable policy rows; the gift catalog snapshot is retained through the immutable room-gift/version reference in the same transaction. After posting, the same transaction records a minimal event and outbox intent. At-least-once delivery may duplicate animations/pushes; clients deduplicate immutable event IDs. Delivery status never changes committed financial status.

Media uses private server-generated pending keys, five-minute presigned PUTs, exact declared length/type and SHA-256 checksum, ten-minute completion expiry, HEAD plus ETag-conditioned bounded GET, JPEG/PNG validation, max 4 million decoded pixels, metadata-free PNG/thumbnail output and an admission limit of two processors. Derived keys cannot be overwritten through pending PUTs. Public serving requires a dedicated configured HTTPS origin and bucket policy/CDN limiting access to approved prefixes; originals stay private. Avatar attachment uses an expected prior asset ID and Profile-owned writes. Agency logo/gift uploads require explicit media administration; agency attachment additionally needs agencies.manage. Banner is unsupported by the current Profile. Gift animation URL references require explicit administrative authorization and configured HTTPS host allowlists, never client object keys; these references are not claimed byte-verified uploads.

Push tokens are AES-GCM encrypted at rest with a separately injected 32-byte key, hashed for unique conflict detection, never exposed in histories/logs/outbox. Bind to an authenticated account/installation/session; session revocation and restrictions invalidate delivery eligibility. Cross-account switching additionally needs logout or valid previous-session consent, never just an installation ID. Preferences explicitly opt in per supported type, initially false. Only fixed templates and nonprivate event IDs enter payloads. Admin announcements use explicit target lists of at most 100, bounded inserts and durable audit; no global broadcast/token scan.

Worker ownership is cmd/worker, fixed 1–4 workers, one claim per worker, bounded provider deadlines, fenced leases, capped exponential backoff/jitter and maximum attempts. Network and image work happen without database transactions. Shutdown cancels and joins workers; expired leases recover after crashes. Disabled providers' topics are not claimed. Asset deletion first atomically retires unreferenced assets; attachments/catalog refs reject retiring assets. Cleanup is delayed past presigned expiry; referenced assets remain retained, old avatar replacement schedules cleanup. Outbox/data retention and load acceptance remain production review gates.

SDK sources: [AWS endpoint configuration](https://docs.aws.amazon.com/sdk-for-go/v2/developer-guide/configure-endpoints.html), [AWS presigning examples](https://docs.aws.amazon.com/sdk-for-go/v2/developer-guide/go_s3_code_examples.html), [AWS checksums](https://docs.aws.amazon.com/sdk-for-go/v2/developer-guide/s3-checksums.html), [Firebase errors](https://firebase.google.com/docs/reference/admin/error-handling), [Firebase Go messaging](https://github.com/firebase/firebase-admin-go/blob/main/messaging/messaging.go). Pin S3 v1.116.0 and Firebase Admin v4.23.0 (module metadata inspected; compatible with the existing Go 1.26.3 declaration). Do not infer real Garage/FCM/SFU delivery from controlled tests.

Implementation refinements: pin AWS credentials helper v1.21.3 and Google auth v0.24.3 alongside the named official SDKs, keeping Go1.26.3. Token OAuth is bounded with explicit service-account type/approved token URI, no asynchronous refresh or SDK payload logger. New canonical-key decoding is opt-in, and old non-room Wallet fingerprint JSON omits new empty room/session fields. deliveries.retry is separately scoped/audited; a failed intent replay cannot write financial postings. Quota/mobile catalog predicates use partial indexes; fanout uses bounded known notification IDs. Independent review remains pending.

Account-switch security boundary: another account's active push binding survives a login that merely reuses its resettable installation ID. Registration conflicts unless the prior account logged out/binding became inactive, or previous_access_token proves the exact prior bound session on that installation. Both account sessions are checked under the same lock; the switch is audited atomically and rolls back on audit failure. Proof is never persisted, logged, returned or included in outbox payloads. Token-hash clashes across other installations fail closed; a push token is not ownership proof. An incomplete client switch has not transferred notification ownership; clients remove the old binding/log out or complete explicit two-session consent before treating push ownership as switched.
