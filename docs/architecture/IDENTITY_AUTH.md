## Schema and locking

Goose migration 2 creates identity-owned app.identity_accounts (random 128-bit hex ID, active/restricted status, display_name/contact_email/avatar_url initialized only on Google signup), identity_google (provider google and stable subject unique, account unique), identity_passwords (one Argon2id PHC credential per account), identity_identifiers (username or phone, globally unique by kind/value and unique account/kind; phone always unverified), identity_installations (random client installation ID and restriction flag), identity_sessions (one family per login, account/installation binding, hashed current access token, access/absolute refresh expiry, revoked flag, authentication time), identity_refresh_tokens (hashed token, session, consumed flag; retained for reuse detection), identity_challenges (hashed challenge, purpose, installation, expiry/consumed flag), identity_proofs (hashed single-use proof bound to account, installation, purpose, expiry), identity_rate_limits (hashed scope, window/count). Foreign keys, CHECKs and lookup/active-session indexes enforce invariants. No staff/business classification column or universal user_type; new accounts have no privileged grants.

Transactions lock installation first, then Google subject advisory transaction lock for signup, then account, then challenge/proof/session as needed. Account lock serializes session issuance, password/identifier changes and refresh/logout-all; refresh token reuse revokes its family and commits before returning failure. Provider calls and Argon2 work occur before transactions. Password mutation rechecks the credential snapshot under lock before writing. PostgreSQL authority is checked on every protected request. Cleanup expiry eligibility uses a fixed PostgreSQL statement timestamp; at most 100 rows per table are deleted per admitted cleanup pass. DB errors fail 503, never permit access. Admin restriction methods remain internal, without HTTP ban routes. Installation IDs can be reset; this is not physical-device attestation.

## API contracts and routine defaults

All routes below are under /api/v1, strict JSON objects, no-store responses and existing request IDs/envelopes. Errors use existing UNAUTHENTICATED (generic login failure), FORBIDDEN (restricted authenticated actor), CONFLICT (alias conflict), VALIDATION_FAILED, RATE_LIMITED with Retry-After:60, SERVICE_UNAVAILABLE. Never echo credentials/provider/SQL errors. Authorization is exactly one Bearer access token plus X-Installation-ID on protected routes. IDs are lowercase 32-hex; opaque bearer strings are 43-character base64url random 256-bit secrets; database hashes are SHA-256 hex. UTC RFC3339 timestamps.

- POST /auth/google/challenges: {installation_id,purpose}, purpose login/password/identifiers -> {challenge_token,nonce,expires_in:300}. Nonce is SHA256(challenge_token) hex; mobile must supply it to Google Credential Manager's nonce option.
- POST /auth/google: {installation_id,challenge_token,id_token} -> for login {access_token,refresh_token,expires_in:900,account_id}; for password/identifiers {proof_token,expires_in:300}. Only login may create an account. Reauthentication requires the already-linked subject and may not create/link accounts.
- POST /auth/password/login: {installation_id,identifier,password} -> token pair. Identifier is username OR phone; email is rejected. Unknown, wrong password and no credential all return the same failure and perform a dummy/current hash verification.
- PUT /identity/identifiers: protected {username,phone,proof_token}; at least one alias required, omitted/empty aliases are not removed; requires fresh identifiers Google proof. Phone is an unverified login alias, never ownership/recovery evidence.
- PUT /identity/password: {installation_id,password,proof_token,access_token,current_password}; installation_id/password required; either password Google proof (setup/change/recovery) or current access token + current password (change only). Proofs are account/installation/purpose-bound. Success revokes ALL existing sessions atomically and returns {reauthentication_required:true}; caller logs in again. No public signup or password reset by phone/email.
- POST /auth/refresh: {installation_id,refresh_token} -> rotated pair; single use, reuse revokes that family. Clients MUST serialize refresh and reauthenticate after ambiguous failures; no refresh retry grace.
- POST /auth/logout and /auth/logout-all: protected empty object -> {logged_out:true}.
- GET /identity/me: protected -> {account_id,display_name,contact_email,avatar_url,username,phone,phone_verified:false}; no persistence-model serialization.

Usernames: trim ASCII surrounding whitespace then lowercase ASCII; 3–32 bytes, starts with a letter, remaining letters/digits/underscore, no Unicode/email. Phone: exact canonical E.164 syntax + followed by 8–15 digits, first nonzero; no guessed country, punctuation or ownership claim. Password: UTF-8, 12–128 bytes, no trimming; Argon2id v19, memory 65536 KiB, iterations 3, parallelism 2, random 16-byte salt/32-byte key; strict fixed-parameter PHC decoding and at most 2 concurrent hash operations per process, fail-fast overflow. Tokens/challenges/proofs never logged.

Sessions: access 15 minutes, absolute family 30 days; refresh replaces current access token immediately; max 5 live families per account, revoke oldest before new issuance. Reauthentication lifetime and challenge TTL 5 minutes. Fresh Google iat must be within 5 minutes (at most 30s future skew) and no earlier than challenge creation minus 30s; nonce must match exactly. auth_time, if present, cannot be future. A fresh nonce proves a new Google authorization interaction, not a newly typed Google password; no stronger authentication-age assurance is claimed. Challenges and proofs are single-use in PostgreSQL; provider token replay against another challenge fails nonce binding. Returning Google login changes only session metadata, never any profile/contact field (including empty fields); no email/phone merging.

Abuse controls precede provider/hash work: durable 60-second fixed windows, 30 requests/IP, 10/installation, password identifiers 5/minute, global expensive-work budget 120/minute; challenges/proofs also covered. Scope values are hashed. RemoteAddr is authoritative for IP bucketing; forwarded headers are not trusted. Deployments behind proxies must arrange reviewed address handling before production. Per-process hash semaphore bounds memory; rejection returns 429. After an admitted abuse check, bounded cleanup removes at most 100 rows per security table (expired challenges/proofs, day-old rate buckets, expired-family refresh rows and then empty expired sessions). Consumed refresh history survives until absolute family expiry for reuse detection. No unbounded queues, cache-based authorization, sticky sessions or SDK calls inside transactions.

## Dependencies and Google verification

Pin coreos/go-oidc/v3 v3.21.0 (RS256-only verifier, shared cached/coalesced Google JWKS) and golang.org/x/crypto v0.59.0/argon2; go-jose/v4 v4.1.4 is used by the verifier and signed tests. Official Google endpoint is fixed https://www.googleapis.com/oauth2/v3/certs; cached keys are reused and a missing signing key triggers a coalesced bounded refresh; custom endpoints/verifiers exist only in tests through constructor injection, never runtime settings. HTTP timeout 5s, bounded transport connections, default trusted TLS 1.2+, no redirects/insecure DB/Redis policy inheritance. Missing GOOGLE_CLIENT_ID leaves Google routes safely unavailable; password/protected flows still initialize. No fake runtime verifier.

Sources: [Google backend verification](https://developers.google.com/identity/sign-in/android/backend-auth), [Credential Manager nonce](https://developer.android.com/identity/sign-in/credential-manager-siwg-implementation), [go-oidc verifier/keyset](https://pkg.go.dev/github.com/coreos/go-oidc/v3/oidc), [Argon2](https://pkg.go.dev/golang.org/x/crypto/argon2). Live Google end-to-end requires configured client and fresh nonce-bound token and may remain NOT TESTED; deterministic signed fixtures must pass.

Deferred: flexible staff permissions, broader profile editing, push registration/delivery, agency membership and audio/video host classification, OTP/SMS, wallet and all later modules. Architecture review remains pending after implementation; no performance claims.


Configuration: GOOGLE_CLIENT_ID is the backend/web OAuth audience; GOOGLE_AUTHORIZED_PARTY_IDS is an optional comma-separated allowlist of up to eight trusted native OAuth client IDs. The backend ID is also allowed. Validate azp when present and require it for multiple audiences; an Android azp is not assumed equal to the backend audience. Username raw input is at most 128 bytes before trimming and normalized ASCII value 3–32 bytes. Identity schema readiness is checked read-only before serving; runtime does not inspect migration credentials/history. The current-user endpoint returns an authorized per-request PostgreSQL snapshot; a restriction committed after that snapshot affects the next security check.

## Step 8 review corrections at 55ead83f

Identity schema Ready is a separate post-Open query bounded by DB_CONNECT_TIMEOUT, preserving an earlier process deadline/cancellation; any failed/canceled check closes its pool and prevents listener/cache initialization. HTTP response Success/Error write failures propagate http.ErrAbortHandler through the existing middleware without another response. Password runtime rules are unchanged: OpenAPI uses the explicitly enforced x-utf8-byte-length extension because native string length keywords count code points. Shared runtime/contract byte-boundary fixtures cover ASCII, Bengali, emoji and mixed text. Generic contract tooling must implement this extension; no ASCII-only restriction was added.
