# Live rooms, agencies and verified activity

Scope and policy: ADR 0012. Contracts: `contracts/openapi/live.openapi.json`. Current evidence: LIVE_AGENCY_VERIFICATION.md. Baseline 645c75c. All independent architectural reviews remain pending unless already explicitly accepted in earlier reports.

## Composition

`cmd/api` loads typed LiveKit config before opening the pool. Agency and workflow routes are available independently of media credentials. Disabled creates no network provider client, never issues tokens or claims media success, and leaves Wallet's existing unavailable-source gate intact. Migration 7 readiness is required for the new module. Enabled additionally requires HTTPS origin/server credentials and injects the official provider/trusted source. Startup never migrates. `config` contains primitive settings and imports no business modules. Module domain interfaces do not import HTTP, SQL or SDK packages. Transport verifies raw webhooks; the adapter uses official SDK APIs and short-lived token grants. No media provisioning, node placement, Flutter/UI, uploads, games or notification delivery is introduced.

Migration 5 adds agencies, delegated managers, host applications, room/session state, membership/seats, ordered provider intents, immutable webhook evidence, connection presence and actor/operation idempotency. Migration 6 adds immutable live policy publications. Migration 8 adds the append-only agency activity-context journal, indexed by account and descending revision. Agency leave appends a NULL context; a subsequent join starts a new calculation floor, while a classification change in the same agency preserves the floor. Historical associations and completed activity remain immutable (owner clarification, ADR 0013). Migration 7 adds append-only account-restriction cutoffs and an active-room-members index. Identity-owned restriction paths call a transaction-bound Live adapter to record the cutoff, leave room memberships/seats and enqueue removals atomically with session revocation. Both administrative and existing internal restriction entry points use it; lifting a restriction neither revives old sessions nor removes the accounting cutoff. Source queries take the first indexed restriction inside an interval, preserving completed pre-restriction activity and preventing later unrestriction from retroactively crediting forbidden time. Existing Wallet associations/financial rows remain in place. New runtime grants omit event/command/policy UPDATE/DELETE and protect completed presence against update. Down migrations fail when owned business/policy data or scoped permission assignments exist, requiring a reviewed recovery plan rather than dropping retained audit/activity. Forward upgrade is additive; index creation is on new empty tables. Production rollout, backup/restore execution and deployment are not authorized.

## Verified event processing

POST `/api/v1/providers/livekit/webhook` retains the exact body and bounds it at 64 KiB. The official SDK verifies Authorization JWT signature/expiry and SHA-256 body binding. Duplicate Authorization headers reject; body/processing limits apply before domain processing. A ResponseController read deadline bounds slow body delivery to the earlier five-second processing deadline on supported real server transports; existing server ReadTimeout remains the fallback for unsupported wrappers. Supported business events are room_started, room_finished, participant_joined and participant_left; other authenticated provider event types are acknowledged without business effect.

Provider event IDs are durably unique and bound to canonical relevant event fingerprints. Exact retries are successful no-ops; conflicting reuse rejects. New events older than 24 hours or >5 seconds in the future reject; previously accepted exact retries remain harmless even outside the age window. Session name must match an immutable server-issued session. The first accepted signed room SID is bound to that session. An unexpected new SID closes business admission and queues provider deletion for that immutable session name; it cannot create qualifying activity or reopen it. Room_started cannot open business admission or reopen a closed room. Room_finished closes admission and abandons unresolved intervals, crediting no inferred disconnect duration.

Participant identities are server account IDs in tokens, but signed unknown identities are removed via durable provider intent. Local membership/account/classification/agency/policy remain authoritative even for events carrying valid provider signatures. Every accepted join queues a provider permission correction, preventing an old token from preserving obsolete publish privileges. Signature verification is not account authorization. Webhook delivery then advances pending provider intent outside the event transaction; failures return 503 for retry. No webhook posts financial entries.

Each participant SID is a unique provider connection identity. An accepted join records conservative PostgreSQL receipt time as start, current association/classification and qualifying publishing role. Delayed joins never backfill time. A signed disconnect closes exactly that SID at min(provider event time, receipt time), never before start. Duplicate joins/left events do not reopen intervals. Left-before-join creates a terminal tombstone: missing start means zero credit. Reconnect uses a new SID; prior connection intervals are not extended. Whole-room events and snapshots never invent participant duration.

Verified provider room absence is distinct from an existing empty room: absence closes business admission and abandons unresolved evidence. A terminal local room unexpectedly present at the provider queues deletion. Missing-disconnect reconciliation compares a bounded provider snapshot to persisted open SIDs. Missing SIDs are abandoned at their start, with zero duration. Still-present connections retain their known starts; snapshots alone cannot establish past activity. Reconnect is required after evidence was abandoned. Provider outage keeps records incomplete and grants no missing time. Long-running unresolved sessions can be inspected; there is no automatic perpetual polling job. Reconciliation is bounded, explicit, scoped, and audited both before calls and at the resulting mutation, so mid-call permission revocation prevents local administrative commit. The prior read-only provider snapshot itself confers no authority.

## Withdrawal integration

The repository implements `agency.ActivitySource`: one bounded query fetches completed qualifying intervals intersecting the requested half-open month/cutoff window, including crossing sessions. It clips open-time revocation and historical association-end boundaries, never returns zero-length intervals, and errors beyond 10,000 records. Open/unknown/unverifiable time is excluded. Existing agency calculator deduplicates/merges overlap and splits calendar days in the immutable policy's explicit IANA timezone, including DST/midnight/month boundaries. No mobile duration is accepted.

The source is injected into the existing Wallet repository only when LiveKit is enabled. Wallet fetches its own fresh source snapshot outside funds locks and rechecks association, immutable policy, business month, current authority and funds in its existing guarded transaction. Current month, 15 days, 120 minutes per day, immediate qualification and editable audio/video policies remain unchanged. No active financial policies/timezone are seeded; configuration absence remains fail closed. Historical activity and saved financial snapshots are never rewritten by new policy/classification changes. Historical transition proration remains the existing unapproved policy dependency; no new proration is invented.

## Queries, resource limits and recovery

All SQL is explicit/parameterized/sqlc-generated. Lists use bounded keysets; room detail caps participants at capacity<=500. Unique current owner/association/occupied-seat and pending-application indexes enforce races. Activity indexes derive from account/end-window queries; inspection has a separate account/SID keyset index. Provider ordering index covers incomplete room operations. No N+1 query occurs per page/session/day; missing-SID completion uses one bounded batch update; application mutation checks use bounded explicit role/account lookups. Association/agency/policy change corrections use one bounded affected-member read and one CopyFrom batch, not per-row provider calls.

All authoritative mutation paths retain Access's existing global security advisory transaction lock. This is safe across instances but serializes these transactions and is a known throughput limit; no production performance/capacity claim is made. Authenticated API database work defaults to an eight-second context, configurable from 100ms to 30 seconds via LIVE_DATABASE_TIMEOUT (remote isolated checks reproduced a five-second guard deadline; multi-instance integration uses 30 seconds to test correctness independently of network latency); source reads retain three-second contexts and event transactions respect the earlier five-second webhook deadline, provider calls 3 seconds by default, operations <=10 seconds and admin reconciliation <=15 seconds subject to earlier HTTP deadline. Total pool connections remain existing configuration; SDK concurrency is eight per process. Pending operation growth needs operational monitoring/retention policy before production. Completed webhook/activity/idempotency retention has no purge job pending audit/privacy requirements. Stale-token media revocation depends on provider correction plus short TTL; self-hosted LiveKit token/reconnect behavior requires real E2E verification.

Existing connections must reconnect after seat/role/classification/policy changes to establish new qualifying evidence. An audience connection is never retroactively upgraded to qualifying time; prior qualifying time stops at its invalidation cutoff. This conservative boundary can undercount time and needs controlled provider/client E2E verification.

Activity policy dependencies before release: approve independent-host eligibility, ownership transfer, historical transition proration. This batch implements the owner-confirmed leave/rejoin rule in ADR 0013 while retaining existing Wallet current-association selection and financial policies. Agency restriction prevents new qualifying media; it does not rewrite previously completed activity or saved withdrawal decisions.

Administrative audit records identify the affected room/agency/account/policy and retain a canonical command fingerprint; member mutations also identify the target account. Agency profile management alone does not grant global host-application approval. Global agency staff cannot delegate themselves as business managers, and host self-approval/self-classification is denied. Muting disables media publication; a moderator role alone does not publish. Signed join receipt/provider timestamp precision and delivery latency can conservatively undercount duration; no live accuracy guarantee is claimed.

Account restriction establishes its local status/session/membership/accounting boundary atomically. Physical provider removals remain explicit durable work and may remain pending during outage/backlog; account restriction responses do not claim media termination. Webhook retries and scoped reconciliation advance that work. There is no automatic continuous-presence billing/checkpoint job: only completed verified intervals qualify, and incomplete evidence is not extrapolated.

Owner clarification is recorded in ADR 0013: active agency context clears on leave and historical records remain. This confirms current-association selection; same-month rejoin starts a fresh qualifying context per the owner's follow-up.

Provider participant desired state is fetched through one bounded member/account/current-association/agency join. The independent provider timeout starts only after those local reads, immediately before calling the SDK; database latency does not consume the provider-specific budget. The existing 10-second total operation bound and 30-second durable lease remain unchanged.
